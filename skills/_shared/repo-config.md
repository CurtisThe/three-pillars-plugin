# Repo Config (`.three-pillars/config.json`)

The single per-repo state file the framework reads on every skill invocation. Stores the small pieces of context that have to survive across invocations and across machines but don't belong inside any particular design.

## Location

`.three-pillars/config.json` at the project root. **Committed to git** — this is shared state, not per-developer state. The directory is bootstrapped at `.gitkeep` time and must NOT be gitignored. If a parent `.gitignore` rule (e.g. `.*`) catches the directory, add an explicit un-ignore: `!.three-pillars/`.

The file is created lazily by the first skill that needs to write to it. A repo with no `.three-pillars/config.json` is treated as a fresh repo (see `## Fail-open behavior`).

## Schema

The shape and constraints are defined by [`repo-config.schema.json`](repo-config.schema.json) (JSON Schema draft-2020-12). Subsections under a top-level `schema_version: 1`:

- `migration` — `completed_at` (ISO-8601 UTC | null), `from_layout` (enum: `"docs+tdd"` | null). Sole writer of `completed_at` is `migrate.py --apply`; SKILL.md wrappers must never set this independently.
- `branch_protection` — `offered_at`, `applied_at` (ISO | null), `declined` (bool, default false), `profile` (enum: `"team-pr-1approval-noforce"` | null).
- `worktree_immunization` — `offered_at`, `applied_at` (ISO | null), `declined` (bool, default false). Tracks whether the `heal-core-bare` hook + `extensions.worktreeConfig=true` have been offered, applied, or declined. Mirrors the `branch_protection` block shape; `first-run.md`'s cheap-path condition reads it in one config-read. Written by `skills/_shared/bootstrap_immunization.py` (`mark_applied()` / `mark_declined()` / `mark_offered()`). Never re-asked after a recorded `declined=true` or non-null `applied_at`.
- `gitignore` — offer (c) in [`consumer-offers.md`](consumer-offers.md) (the `.handoffs/` ignore rule): `handoffs_declined` (bool, default false) — the sticky "no" that settles first-run condition 8 alongside a present rule, written by the offer's decline (`repo_config_load.py set gitignore.handoffs_declined true`); an absent key means not declined.
- `local_implement` — opt-in per-task cheap-tier dispatch (`/tp-phase-implement --local`, `/tp-run-full-design --local`): `enabled` (bool, default false), `model` (default `"haiku"`), `fallback_model` (default `"sonnet"`), `full_design` (bool, default false), `escalate` (bool, default true), `max_retries` (int ≥ 0, default 2), `max_files` (int ≥ 1, default 3), `default_run_flag` (enum `"on"` | `"off"`, unset = off: `"on"` makes `launch_design_run.py` forward `--local` on every launch, only when `enabled` and `full_design` are also true and the runaway-ceiling capability gate passes; `--no-local` removes it for one launch), `client_timeouts` (the orphan reaper's applied/declined record `{applied_at, declined, values}`; `values` holds any subset of the four client-timeout env keys as ints ≥ 1; no default). An absent block means the feature is off. A partial block is merged over the defaults by `skills/_shared/local_implement_config.py`, whose `--check {interactive|full_design}` prints the one missing key when `--local` is refused (`full_design` needs both `enabled` and `full_design`). No task starts on Opus: every task starts on the local rung; one without a valid **Targets** field (`skills/tp-plan/SKILL.md`) has no oracle, so a cheap PASS lands only when an Opus diff review accepts it (`accepted-by-review`), and Opus is reached only by escalation after a failed attempt or a rejected review.
- `role_engines` — **deprecated** (one-cheap-engine: the launcher's `TP_LOCAL` / `TP_LOCAL_MODE` and `cheap_engine.py` decide; the key is still read, never required). Engine per routable role (local-role-routing), resolved by `skills/_shared/role_engine.py`. Exactly four keys — `council_member`, `review_finder`, `context_scout`, `explainer` — each taking `"local"` or `"opus"`; the value changes nothing — `local` and `opus` are both ignored, the engine follows the run (Sonnet, or Strata under `--local`), and a set key only adds a deprecation note (one exception, `explainer: opus`, below). An unset `context_scout` follows `review_finder`. The **judgment roles have no key here** — the synthesizer, the final check and every auditor always run on Opus. An absent block is every role on the run's cheap engine.
  - **`explainer`** (explainer-agent) — read only by the explainer's `explain_engine` layer (`skills/_shared/explainer/`), and the drafter is a cheap site under one-cheap-engine: unset = the run's cheap engine drafts, Sonnet, or Strata under `--local`. `local` = deprecated like the other keys and changes nothing: the drafter still follows the run, Strata under `--local` and Sonnet when there is no backend, when the slot is busy or when the run is not `--local`. `opus` = Opus drafts every kind (the one `role_engines` value that still acts: the design's honest switch). The per-kind `explainer.drafter_override` wins for its kind. The Opus check is fixed and has no key.
- `explainer` — the explainer's switches (explainer-agent), read by `skills/_shared/explainer/explain_config.py`, which merges the block over its defaults and drops each bad entry with one warning (never a hard error). `enabled` (bool, default `true`) is the off switch: `false` turns the explainer off and restores today's PR flow byte-identically. `publish_artifact` (bool, default `true`) publishes the HTML page as a private claude.ai artifact when the Artifact tool exists; `false` keeps the local HTML only. `drafter_override` (object, default empty) pins one kind's drafter to Opus and wins over `role_engines.explainer` for that kind; its only keys are `pr-brief` and `human-escalation` (the two Opus-checked kinds) and its only value is `"opus"`. An absent block is every default.
- `strata_spawn` — policy for Strata-routed spawns (local-role-routing), read by `skills/_shared/strata_spawn.py` (busy slot), `skills/_shared/child_permissions.py` (permission rules) and `skills/_shared/child_sandbox.py` (Bash sandbox).
  - **`strata_spawn.busy`** — `"fallback"` (default) waits a 3 s grace (`BUSY_GRACE_S`) on a busy slot, then accepts the Sonnet-served reply; `"wait"` polls the slot, never uses Sonnet, and halts at a 4 h ceiling. An unknown value warns and uses `fallback`.
  - **`strata_spawn.permissions`** — rules a child launch **adds** to its shipped lists. Two keys, `allow_extra` and `deny_extra`, each an array of rule strings (`Tool` or `Tool(matcher)`). A child already launches with `--permission-mode dontAsk`, a shipped allow list plus `Edit`/`Write` scoped to its own worktree, and a shipped deny list. An entry that is not a rule string warns and is skipped; the shipped deny list only grows — it can't be removed by config.
  - **`strata_spawn.sandbox`** — the child Bash sandbox: `"off"` (shipped default) or `"on"`. On, a site-S1 child launch merges the sandbox block into the attempt worktree's `.claude/settings.local.json` (git common dir and TMPDIR writable, `<common>/hooks` and `<common>/config` denied). `TP_CHILD_SANDBOX=on|off` overrides the key for one run. Where the sandbox can't run the child runs unsandboxed with one warning line.
- `github` — the PR-author bot account: `pr_author_account` (the login automation writes run as, token fetched per call from the gh keyring), `used_for`, `review_requests`, and `per_developer_author` (`"off"` default | `"self"`). Under `self` a developer without the bot in their keyring runs automation writes (PR create, digests, replies, labels) as their own gh login (the bot still wins when its token is available), and the merge gate also trusts the PR author's own review-proof digest, self-attested and never for a fork PR or an automation author; `human_approved` still needs a non-author human. An unknown value raises on every write and is read as `off` at the gate (the config prune drops it with one warning). See `human-approval-howto.md` §Team repos: contributors without the bot.
- `forge` — what this repo's origin is (forge-interface): `kind` (enum `"github"` | `"gitea"` | `"other"`), `host` (ISO-free origin host | null), `web_base` (instance base `scheme://host[:port]` | null), `recorded_at` (ISO | null). **Writers**: `skills/_shared/forge_config.py::record_kind`, called by first-run on a non-GitHub origin — it records **once** (`kind` already set → no-op, no byte rewritten) and **merges**, never replacing an operator value; or the operator, once, when detection cannot classify the origin (an ssh alias, a custom-port Gitea): set `web_base` alone. **Readers**: `skills/_shared/forge.py::resolve` (`web_base` is its highest-priority base; `kind` its highest-priority class) and `first-run.md` conditions 3 and 7. **Hand-editing overrides detection** — a recorded `kind` is never re-derived. When `forge.resolve` reports `no web base`, the operator either sets `forge.web_base` to the reachable instance base or sets `forge.kind: other` to silence the one setup line. No credential is ever stored here (a Gitea token stays in the operator's `tea` config / env).
- `review` — code-review / merge-gate posture. Includes `approval_survives_safe_base_sync` and `base_sync_carry_max_chain` (documented below), plus `expects_copilot`, `require_human_approval`, `automation_identities` (see `repo-config.schema.json` for those).
- `models` — per-role dispatch model, read by `skills/_shared/model_policy.py`. `review`, `fix` and `classifier` each take one of the four Agent aliases (see `model_policy.AGENT_ALIASES`) dispatched via the Agent tool's `model=`; defaults `review: opus`, `fix: opus`, `classifier: sonnet`. The fourth key, `design_run` (a `claude --model` argv — an alias or a `claude-<family>-…` id, either optionally suffixed exactly `[1m]`, never `inherit`), defaults `sonnet[1m]` (a repo may pin `opus[1m]` back; the 1M-context window: a bare `opus` behind the `claude-hybrid` router gets 200k and compacts on the first turn); `model_policy.py` is the one source of that default for every launcher. There is no `audit` key: audits always dispatch Opus. **`models.design_run: fable` is a rare exception, set only by hand in this file, never a default and never suggested by any skill or example config** — each fable design run prints one warning and appends one `decisions.md` entry.
  - **Cheap-tier slot keys** (cheap-tier-offload): `runbook`, `base_sync_splice`, `pr_fix_reproducer`, `classifier_judge`, `history_line`, `handoff`, `docs_draft`, `task` and (cheap-tier-review-prep) `review_slice`, `review_refs`, `ci_log_triage` and `repro_scaffold` are read by `skills/_shared/cheap_tier.py`, not `model_policy.py`. Each takes one rung from its slot enum in the schema (`code` for `runbook`; a `local-*` rung or its Sonnet mirror otherwise; `task` takes only `sonnet-xhigh`; `repro_scaffold` takes the xhigh pair, the other three prep slots the medium pair). Every slot ships **on** at its local-first rung (`task`=`sonnet-xhigh`, `runbook`=`code`, `base_sync_splice`/`pr_fix_reproducer`/`repro_scaffold`=`local-xhigh`, the rest `local-medium`) except `handoff`, which stays Opus; the key is now an **override** — a rung, or `"off"` to opt the slot out of the repo. A key naming an excluded role (any review, audit, gate, design or merge step) or an unknown role is refused by `cheap_tier.load_slots`: `cheap_tier_cli.py` exits 2 and the site keeps today's path. The site protocol is [`cheap-dispatch.md`](cheap-dispatch.md).
- `design_run_backend` — the backend a design-run window starts its orchestrator on (`"route"` | `"direct"`, resolved by `skills/_shared/design_run_backend.py` at `launch_design_run.py`), **not** the model key (`models.design_run` is the `claude --model` argv). Default `"route"` = today: the Homelab launcher plans the window's backend from the folder's routes row. `"direct"` (the `--direct` flag for one run) puts the launcher's seat role `CLAUDE_LAUNCHER_ROLE=seat` in the window command, making the launch direct plus Remote Control — set it in this file **only after the S4 proof run is recorded in the design's `decisions.md`** (its Strata children still reached the router: `router_checks.py --since` shows Strata requests > 0 at about 0 checks per request). With no launcher in the launching env (`CLAUDE_LAUNCHER_OWNED` unset) the seat role is inert: the launcher prints one `W:` line and launches plain `claude`. A value outside the enum is pruned by the loader with its warning and the run stays `"route"`.
- `design_run_mcp` — which MCP servers a design-run window loads (`skills/_shared/design_run_mcp.py`, applied by `launch_design_run.py`): `allow` (list of server names looked up in the project `.mcp.json` and the profile's `.claude.json`; default `[]`). The window starts with `--strict-mcp-config --mcp-config '<json>'` carrying only the allowed servers, so an unused one (claude.ai Notion is ~60 tools) stops widening every turn's cached prefix; list a name to opt that server back in. The launch prints one `design-run MCP:` line naming what loaded and what was skipped. A name with no definition is reported (`not found`), never fatal; a Claude Code build without `--strict-mcp-config` leaves the command unchanged with one `unchanged` line.
- `merge_from_main` — `generators[]` (`path`, `write` argv, optional `check` argv, optional `timeout` seconds ≥ 1, `inputs[]` source files the generator resolves, `cwd` directory the argv runs in), read by `/tp-merge-from-main`'s regenerate resolver; absent means generated-file conflicts defer as before. `generator_offer` {`offered_at`, `declined`, `offered_paths[]`} is the record of generated files the catalog already offered, so the detector never re-offers them.
- `cheap_tier` — `default_run_flag` is **deprecated** (enum `"on"` | `"ab"` | `"off"`; the cheap tier is always on, so the key is read only by the shared resolver `skills/_shared/cheap_tier_default.py` (`resolve` / `resolve_root` / CLI) at `/tp-merge-from-main`, `/tp-post-merge` and the fleet launch lines; the launcher adds no flag). An explicit `--cheap-tier[=ab]` wins; `/tp-pr-iterate` and `/tp-pr-fix` stay explicit-only.
- `retro.enabled` — boolean, default `false`: when `true`, `/tp-design-learn` runs the retro step; absent or `false` skips it.
- `fleet.max_live` — integer ≥ 1, default `2`: the live-run cap a fresh fleet roster starts with (`fleet.diff_balloon_factor` is the separate diff-balloon guard multiplier).
- `TP_LOCAL_MODE` (environment, not a key) — the busy policy: `fallback` (a busy slot is served on Sonnet), `wait` (poll the slot, never Sonnet, halt at the ceiling) or `exclusive` (the same as `wait`); unset = `fallback`, an unknown value warns and uses `fallback`.

`additionalProperties: false` at every level. Unknown keys are a hard validation error — a typo in a write path fails closed rather than silently storing junk.

### `review.strata_finder_segment`

Segments a large diff for Strata review finders (`skills/tp-pr-iterate/scripts/finder_segments.py`; `skills/tp-pr-iterate/strata-finders.md` §Large diffs). An object `{max_lines, max_files, max_segments}` (integers ≥ 1; defaults `600`, `10`, `4`) or the literal `false` to turn it off. A diff over `max_lines` changed lines or `max_files` files runs one Strata finder per segment; under the limits, or on Claude finders, behaviour is unchanged.

**`review.strata_finder_lines_per_cap`** (integer ≥ 1, **no default**) caps the size of a *first-attempt* segment: set below `max_lines`, no planned segment is larger than the figure unless it is one hunk, and each segment's deadline `fraction` is its lines over the figure. The engage threshold stays `max_lines`/`max_files`, so a diff under the limits is still not segmented at any figure. Absent, invalid, or at or above `max_lines`, sizing is exactly today's. The key is **set from the telemetry** — the per-segment `lines`/`outcome` rows the round writes to `segments-merged.json` (`finder_segments.py merge`) — never defaulted by the framework, because a sizing change follows the data (design finder-cap-coverage).

### `review.approval_survives_safe_base_sync` + `review.base_sync_carry_max_chain`

The **base-sync approval carry** (`approval-survives-safe-base-sync` design): whether an approval or proof-of-review digest anchored on a head *before* one or more mechanical base-sync merges is still trusted after the head has moved.

- **`approval_survives_safe_base_sync`** (boolean). **Default-off**: absence, a corrupt/non-dict `review` block, or any truthy-non-bool value all fold to `false` — the carry activates ONLY on the literal boolean `true`. This is the deliberate *inverse* of this block's other keys (whose strict default is *on*): here the strict default is *off*, since the carry is a narrow, opt-in relaxation of an otherwise-strict gate.
- **`base_sync_carry_max_chain`** (integer, `1`–`20`, default `5`). Caps how many certified base-sync merges the carry's first-parent walk will cross before giving up; a chain past the cap fails closed with a re-approve-on-current-head remediation.
- **`living_doc_handres_preserves_approval`** (boolean, default `true`). The living-doc hand-resolution carry, nested inside `approval_survives_safe_base_sync`; only the literal `false` opts out (back to the strict byte-exact carry). Read from committed HEAD like the keys above.
- **`proof_neutral_carry`** (boolean, default `true`). The proof-neutral carry (`proof-carry-trivial-commits`): a review proof is carried across up to 4 proof-neutral commits (living-doc `.md` edits, comment-only `.py` edits, and a base-sync merge whose hand-resolved paths are all living docs, at most 200 changed lines). Only the literal `false` disables it. It is **not** nested under `approval_survives_safe_base_sync`, and it carries only the review proof: the `ci_local` stamp and the human approval are not carried. Read from committed HEAD like the keys above.
- **Committed-HEAD read**: these keys are read via the existing `_load_repo_config` path (`git show HEAD:.three-pillars/config.json`), the same mechanism `require_human_approval` already uses — **an uncommitted edit to this file cannot enable the carry**. Flipping the carry on is itself a committed, reviewable change.
- **What "certified" means**: the carry never trusts a PR comment, a local state file, or a producer's claim. Each link in the chain is independently re-derived from git objects alone by `skills/_shared/base_sync_cert.py` — merge shape (first-parent discipline), the second parent's ancestry on the base branch, an allowlisted `merge-tree` recompute, byte-equality outside the conflicted region, and a resolver byte-reproduction over a zero-drop backstop. The `basesync-cert.v1` PR comment posted by `/tp-merge-from-main` step 7 is audit trail only — forging, deleting, or misattributing it changes nothing (the gate never reads it).
- **Seat-locally-ahead over-block (accepted trade-off)**: when the seat carries local commits ahead of the freshly-fetched base tip (e.g. unpushed `three-pillars-docs/tp-designs/orchestration/` commits per `topology.md`'s orchestration-paper-trail allowance), the oracle checkout is no longer an ancestor-or-equal of the fetched base tip, and the carry **fails closed with no carry** even though the underlying chain may in fact be certifiable. This is a deliberate over-block, not a bug: remediate by pushing the seat's base branch (so the fetched tip catches up) or by re-approving on the current head. See `three-pillars-docs/completed-tp-designs/approval-survives-safe-base-sync/detailed-design.md` for the full independent-oracle guard spec.

Release tracking is deliberately not part of this schema. Releasing the three-pillars plugin itself is a dev-only flow documented in `three-pillars-docs/RELEASING.md`; downstream projects that install the plugin have nothing to release, so a `release.*` subsection would be dead weight (and confusing) in their config.

## Atomic write

Every write goes through tmp-file-and-rename, so a partial write (process killed mid-flush, disk full, etc.) leaves the previous valid file intact:

```python
import json, os, tempfile
from pathlib import Path

def write_config(repo_root: Path, data: dict) -> None:
    target = repo_root / ".three-pillars" / "config.json"
    tmp = tempfile.NamedTemporaryFile(
        mode="w", dir=target.parent, prefix=".config.", suffix=".tmp", delete=False
    )
    try:
        json.dump(data, tmp, indent=2)
        tmp.flush()
        os.fsync(tmp.fileno())
        tmp.close()
        os.replace(tmp.name, target)
    except Exception:
        os.unlink(tmp.name)
        raise
```

The `tempfile` lives in the same directory as the target so `os.replace` is a same-filesystem atomic rename (POSIX guarantee). Never write to `/tmp/` and then move — that crosses filesystems on many systems and falls back to a non-atomic copy.

## Schema version upgrades

`schema_version` is a hard `const: 1` today. The forward/backward compatibility rule is:

- **Newer code reading older config**: must handle. If a v2-aware code release reads a v1 file, it migrates the v1 shape to v2 before any further work and writes the upgraded config back atomically.
- **Older code reading newer config**: must fail closed. If a v1-only code release reads a v2 file, JSON Schema validation rejects it (`schema_version: 2` doesn't satisfy `const: 1`). The skill stops with a clear "this repo's config is from a newer framework version; upgrade your installed framework" message rather than running with partial understanding.

Adding a `schema_version: 2` requires a new schema file (`repo-config.v2.schema.json`), a documented v1→v2 migration function, and code that reads either version.

## Fail-open behavior

The framework prefers to keep working when the config is missing or unreadable, **for cheap-path operations**:

- **Missing file**: treat as a fresh repo; `first-run.md` triggers its detection paths and prompts the user. No error.
- **Parse error / invalid JSON**: log a one-line warning, treat as missing, fall through to `first-run.md`. Do not delete or rename the broken file — leave it for the user to inspect.
- **Schema validation error**: degrade per key, not per file. The shipped validator (`skills/_shared/repo_config_load.py`) prunes only the invalid key with a one-line warning; the valid keys still apply. Only a `schema_version` mismatch or an unparseable file makes the config absent (the `schema_version` case keeps the upgrade message the reader surfaces).

The exception is **write paths**: a skill that needs to *update* config (e.g. `migrate.py --apply` setting `completed_at`) reads-validates-mutates-writes. A read failure mid-update is a hard error — the skill stops rather than overwriting an unreadable file with a partial guess.

`first-run.md` codifies the cheap-path early-exit (`if config exists and all three subsections are non-null, return`) so the hot path stays a single read.
